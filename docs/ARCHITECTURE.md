# 架构

Tako 是两个进程：**原生 app**（Swift）有系统权限，管小章鱼、窗口和动手；**大脑**（Python）管会话、模型和规则。面板是大脑提供的一个网页，显示在原生 app 的窗口里。

```
             ┌──────────────── 原生 app（Sources/native）────────────────┐
             │ 小章鱼   窗口跟随   挪窗口让位   填入/操作   听声音   更新 │
             └───┬───────────────────────┬──────────────────────────────┘
       网页里的面板 │              /native/next 取命令，/native/result 回结果
                 ▼                       ▼
             ┌──────────────── 大脑（Sources/brain）────────────────────┐
             │ routes → Companion（chats + turns + hands + lecture + agents） │
             └───────────────────────┬──────────────────────────────────┘
              codex_runtime 或 office（标准输入输出）
                                     ▼
          Codex app-server → 模型，或办公智能体（WorkBuddy、Qoder）→ 它家的模型
```

大脑永远不直接碰窗口：要点、要填、要看，都发一条命令给原生 app。原生 app 不判断该不该做这件事，只判断这一下能不能按。

## 两种线程

判断改动能不能这样写，先看它跑在哪种线程上：

- **主人的线程**（`turns.Brain`）：只跑主人在面板里说的话（和其他 Agent 替主人交来的事），有工具、有 shell。分两种，做法完全一样（`Turns._brain`）：
  - **常驻线程**：每段对话一条——每个窗口、每个微信或钉钉聊天、桌面各一条（按 `conversation_key`）。主人在哪段对话说话就进哪条，没有调度模型；同一段对话按顺序，不同对话并行。一段对话里干活中途说的话都并进正在做的那件事（`_join`，见下面「一轮进行中主人又说话」）。`config.json` 的 `per_conversation_threads: false` 关掉它：所有对话映射到同一条（键是空字符串），就是原来的单一大脑——两种行为是同一套代码，差别只在 `_brain_for` 这一处映射。
  - **触手**：常驻线程这会儿接不了时，这一件事开一条临时的，做完退订。三种情况，各记一个固定词：`busy`（关掉开关时大脑在别的窗口忙）、`summarizing`（本对话的线程在压缩）、`full`（常驻线程到上限且都在干活）。
  - 新开的线程（常驻或触手）带 Tako 的规矩和工具、主人是谁（`about-me.md`）、托付记忆、最多 2,000 字的本体索引（`ontology.Memory`）和本段对话在线程开始前说过的话（`_said_here`）。详细内容按索引中的出处读。`Brain.told` 记录已经提供的索引、今天的事项和写法笔记，有变化时再给。
  - 别的线程做完的事（`_tell_threads`）：每件答完的事写一行（主人原话和结果开头），每条常驻线程下一轮各听一次（`Brain.heard`），做这件事的那条线程不听，线程出生前的不补（它开头那份记录里已经有）。微信里排着的一步放好或没放成，也这样只告诉那段对话的线程。关掉开关时这正是原来的 `limb_news`：只有触手做的事告诉大脑。
  - 常驻线程最多 `conversation_threads_max` 条（默认 6）：要开第七条时退订闲得最久的那条；都在干活就这一件走触手。一段对话 `conversation_thread_idle_minutes`（默认 30）分钟没动静就退订。下次在那里说话、或重启后，都从记录续上：同样的开头。共用的那一条不受这两项影响。
- **一次性线程**（`Turns._reader`）：听课笔记、从改动里学、开场白、反馈提炼。没有任何工具，用完就退订（`thread/unsubscribe`），Tako 这边不再保留它的事件。所以窗口或材料里写的话，什么也动不了。别人的微信、钉钉消息不触发任何一轮：主人开口时才读那段对话（`Chats._said_since`），读到的只是材料。

Codex 一次性线程默认通过 `baseInstructions` 使用短底稿；`TAKO_READER_SHORT_BASE=0` 可回退。实际节省量和回复质量需在隔离 `TAKO_HOME` 中用真实 Codex 对照 `metrics.jsonl` 验证，ACP 不使用此字段。`python3 scripts/measure_entrust_context.py` 用假 Codex 比较当前与 `main` 的指令和工具声明字数，不衡量真实 token。

工具调用只认登记在 `on_thread` 里的线程，也就是主人的任务所在的线程（`Hands.on_server_request`）。常驻线程只在它上面有主人的任务在跑时登记，一轮结束就撤下，两轮之间它请求什么都被拒。给一次性线程加工具，就是拆掉这条防线。

`metrics.jsonl` 的 `turn` 行：`path` 是 `own`（每段对话一条）或 `shared`（关掉开关），`brain` 是否在常驻线程上，`limb` 走触手的原因，`cold` 这条线程是不是这一轮才开的，`threads` 当时有几条常驻线程；`compact` 行多了 `path` 和 `ended`（`done`、`failed`、`left`）。都是数字和固定词。

同一任务重复看窗口时，`Hands._look` 在内存比较窗口身份、原生返回的全部状态（含截图）和解析出的文件；完全相同才复用上一条结果，缺少窗口 ID 或截图时始终完整发送。`config.json` 的 `look_dedup: false` 可关闭这项比较。

## 桌面与托付

桌面是同一面板的 `desktop` 对话，仍用 `Job`、它自己的常驻线程（关掉开关时是共用的那条）和同一份记录。点自由状态的小章鱼走 `/desktop`，不认领前台窗口、不截图、不读微信、不生成开场白，也不挪任何窗口。对话超过面板近期缓存时，从原来的记录恢复。其他 Agent 可指定 `window: "desktop"`，或在 Tako 没粘窗口时不指定窗口。

主人这一轮的 `entrust` 工具写好递回的话、可选的 ISO 日期时间和可选的地方（应用名、标题字或聊天名：微信或钉钉里的那个人、那个群）。相对时间用 `after` 的数字和单位，由程序加到收到主人那句话的精确时刻；补充指令各自记时，回复给模型的是实际到点时间，不靠模型算秒。钟点仍用 `due`，早于主人开口时刻会被拒绝。省略地方沿用任务自己的窗口，在微信或钉钉的聊天里交代的沿用那个聊天（`Job.chat_name`），空对象表示不限地方。工具必须引用这轮主人原话，包括 `turn/steer` 的补充；工具入口仍只向 `on_thread` 的主人任务开放。准备材料、做草稿也是这一个 `Job` 的工作，不在到点时另叫模型。

`records.py` 在原来的每日 Markdown 追加 `r: entrusted` 条目，以原 `Job` 的记录 id 关联；创建、改期、删除、递回、完成、打开、稍后、没理会都在这里，动作标识沿用原值，旧记录照常重放。创建时记录完整信息，后续只写变化，重放时按 id 合并；通知排程结果从系统查询，不追加记录。`Entrusted` 启动时重放全部日期，内存索引不是第二个库；尚未完成的托付不随七天面板缓存过期。下次主人说话时，当前托付与近期结局进入这一轮已有的上下文。没有模型巡查。

`entrusted.py` 不导入模型运行时。启动时同步一次托付；空手时没有到场窗口观察、大脑轮询，原生侧也没有为它设的定时器。有托付时由事件触发判断：应用切换、最前应用经辅助功能告知的焦点窗口和标题变化、到点定时器、主人离开两分钟后回来（`Attention`）；另有一个兜底的低频检查（拿着事时 30 秒，正举着泡泡或展开手里预览时 3 秒，同时复查展示相关的系统电源断言）；只发命中的 id 和安静状态，应用名、标题不发给大脑，不写日志、不落盘。非安静时，微信在最前且有聊天地点的托付才复用现有顶部条截取和本机识字；画面未变不做 OCR，切走停止，缺录屏权限静默不匹配，不为此另加定时器。钉钉在最前且有聊天地点的托付时，`tick` 经辅助功能读它正打开的聊天名（`DingTalk.openChat`，约十几毫秒，不截图）；钉钉里点按后由同一个 `noteChatActivity` 在 0.15 秒和 0.8 秒各叫醒一次，读不到就静默不匹配。

贴窗跟随与到场比对共用 `HeaderCapture` 的内存中截取和识字请求；应用切换及键鼠操作后短暂检查，稳定后停止截取；点按之前开始的那次截取不算点按之后的答案（`notBefore`）。粘在最前的微信或钉钉上时，到场比对不另截、不另读，直接用大脑确认的那个聊天名（`Controller.openChat`，来自 `/current` 的回复）；没粘着时才本机自己读。两边比聊天名用同一条规则（`sameChatName` 对应 `guards.same_chat`）：字一样，或者是标题在一个断开处之前的简称（小林 对 小林-市场 助理），不认包含（小林 不是 小林妈妈），也不认没起名群标题里的某个成员（阿青 不是 阿青、老马）。面板取色只在面板打开时，由打开、换窗口、切回应用和系统外观变化触发，不再周期截取整窗。

每次只递一件。已经递出的泡泡保留到主人回应或场景变化，后来的候选不替换它。手空时先递已到点的，按钟点从早到晚，然后是会前、到场和转场。忙碌、安静、全屏、离开或打字时等合适时机。到点件绕过每天六次和连续忽略三次的限制，也不会在展示满 60 秒时记作忽略。普通件展示满 60 秒且未悬停记一次忽略，留在当前场景直到场景变化。连续三次忽略后只持有，互动或改期重置。离开至少两分钟后回来、或别的任务结束，是转场机会。带地方的托付先等四小时给到场机会，再也可在转场递。忽略或推迟后，同一件的转场间隔依次为 30 分钟、1 小时、2 小时、4 小时、8 小时、16 小时，最多 24 小时；从记录重建，主人另定时间照新时间。新建或刚修改的托付不会在它自己的任务结束时马上递回。泡泡上是「✓ 做完了」和「稍后」。完成调用 `done`。稍后调用 `later`，先说实际的等待时间（`later_line`），再收回。点完整气泡的正文或留白，经 `/entrusted/look` 打开去处。窗口的事去那个窗口并显示那段对话（`going_to`），微信的事打开指定聊天，钉钉的事去钉钉，由主人打开对应聊天。桌面的事若没有可打开的窗口，在小章鱼旁显示原对话。打开后仍是待办，记录 `looked`，下一次递回至少隔半小时。点系统通知正文同打开。动作直接追加记录，不调模型。

新的到场或转场刚被识别、或主人正在输入时，普通托付先伸半手，只显示短标签。指针靠近，或停顿并经过 1.5 秒后，由同一条递回展开按钮。从完整递出才开始计算日限和忽略。到场件的泡泡完整展开后，主人没有悬停或点按，半小时内回到原处不再递同一件，手里件数照旧，跳过这次不占日限、不计忽略。展开时间随托付记录重放，系统提醒事项沿用本地节奏记录，只存编号和时间等节奏数据。到点能接过尚未递出的半手。半手复查用一次性唤醒与已有前台观察；安静时短标签也收住。

贴着窗口就是专注：只递到点的（原地递，不离开窗口）和与这个窗口有关的（`tick` 只在最前的就是贴着的那个应用时才算到场，例如贴在钉钉上、主人切到了托付里那个人的聊天）。离开回来、别的任务结束这些转场都不在贴着时递，等它回到桌面形态；把它从窗口上拿下来（`peelOff` → `Entrusted.peeled`）本身就是一次转场。

禁言、隐藏、自动安静都阻止泡泡递回；到点仍由系统通知。禁言和隐藏记在运行目录 `quiet.json`，重启恢复；右键菜单可取消。自动安静由设备及电源断言决定。自动状态只在内存，手里泡泡只显示件数，悬停也收住正文。

其他 Agent 也可通过既有 agent 令牌直接托付、查询和撤回，不调用模型：`tako entrust "记得查看报告" --after 3600 --app Keynote --from Calendar`，`tako entrustments`，`tako entrustments ID`，`tako unentrust ID`。传进来的正文和来源写进同一桌面对话记录；查询包含完成、打开、稍后等结局。

来源名由调用方填写，并不是经过认证的身份：持有共享令牌的本机调用方可以冒用另一个来源名并撤回该来源的托付。令牌只应交给互相信任的调用方；来源限制不能作为隔离不同 Agent 的安全边界。

`HandOver.swift` 给身体已有的手一个目标，服装不长新手：身边卷住墨泡泡；伸手时先探一点、停一下，再弹性递出；点完成后气泡破成墨点并露出满足表情；点「稍后」先在泡泡里说一句什么时候再来，再收回身下（`sayThenTuck`），没理会慢一点收回。鲸鱼娘戳破时还会轻轻喷水。泡泡画在原来的 goo 图层上，不新增面板。手里有东西时不牵鼠标。`--showcase=none,entrusted` 演全部过程；`TAKO_HOME=/tmp/tako-preview-home /path/to/Tako --showcase-frames=/tmp/tako-frames --showcase=none,entrusted,real` 离屏渲染 Goo 图层，不启动大脑、不连接网络、不开窗口、不申请录屏权限。独立编译二进制时可设 `TAKO_SHOWCASE_ART` 为项目 `Sources/art`，以加载鲸鱼娘贴图；正式 app 仍用内置资源。

系统通知用 `UNUserNotificationCenter`：在托付那一轮申请一次授权并排本地时间触发器，退出后也由系统负责；同一通知状态只在变化时告知，未开启时面板提供打开系统设置的按钮。修改、完成、打开、稍后、删除按原 id 替换或撤下待发及已发通知；通知按钮是「✓ 做完了」「打开」「稍后」，点通知本身也可打开；启动或托付变动时同步记录重建出的权威集合，从系统设置回来再核对。通知无声音、无角标，遵守系统 Focus，不用 critical 或 time-sensitive 绕过。同步按记录 revision 拒绝旧快照，并串行处理排程，避免改期被旧请求覆盖。已过点且未排成的件从托付记录恢复，在安静解除、主人回来或重启后第一次可递的前台时机补递；系统先前排好的通知仍按原钟点送达。

默认输入麦克风或任一系统摄像头的公开 running-somewhere 属性显示正在使用时，Tako 进入自动禁言，不递主动泡泡；自己的说话录音不触发麦克风禁言，设备接口无法区分同时使用同一麦克风的其他应用。观察设备状态不申请麦克风或相机权限。电源检查还读前台防止显示器休眠断言，以及各进程明确描述屏幕共享、屏幕录制或远程桌面的活动断言。只在本机比较断言类型和名称。系统信号的已知覆盖边界见 PRIVACY.md。系统通知包含托付正文，其共享和锁屏预览由系统设置控制。系统通知按系统专注模式处理；自绘泡泡不读取专注状态、不请求额外授权。

自由状态下递回时，小章鱼游到最前窗口旁边递；贴着时就在原地递，不去别的窗口。大脑还有任何主人任务在跑时先排队，系统定时通知照常到点，任务结束后再递，不让 Acts 和递回抢同一只手。

`_hold_fill` / `_place_when_back` 等待的是确定窗口、主人真的到了且手停下，最后需要动输入框；托付的到场仅是匹配前台应用名和标题，不能借此操作窗口，也允许按时间和转场递回。两者都经原生侧观察窗口，但不合并观察条件，否则会扩大自动动手的授权或把到场提醒错误限制在需鼠标空闲的情形。

## 主动性的梯子

Tako 可以独立递回托付，也支持接入外部事项服务。底下只有一个机制：托付（`entrusted.py`）和它的三个时刻（到点、见人、到场）；`ladder.py` 只按主人手上有什么逐级点亮来源，不做设置页、不另建存储、不开第二个入口。`ladder.json`（600）只放阶段、计数、时间和开关，不放任何人的话。都不调用模型。

**一次只有一件。** Tako 自己主动拿到主人面前的东西，出不出、什么时候出，只在一处决定：`ladder.Ladder.next`。顺序固定：
- 必需的三步：模型（`Setup` 没就绪）→ 辅助功能 → 录屏与系统录音。每一步是面板顶部的一张卡，面板为每一步自己打开一次（`side.html` `openForStep`），做完自己消失、接着下一步；系统自己的弹窗只在轮到那一步时出现一次（原生 `askSwitch`：启动时不再弹辅助功能，录屏要等 `screenTurn`）。模型这一关，本机已有的登录一律直接用上：Codex 已登录就是就绪；没有时，已登录的办公智能体（WorkBuddy、Qoder、千问办公）由 `Setup._adopt` 在后台读一次磁盘上的登录、直接接上（隔离运行不做），面板只说一句「用的是你在 X 的登录，已经接上了。」；都没有才出模型卡。
- 首次体验：一生一次。用过 Tako 的人（启动时已有托付或对话记录）直接算做过。
- 邀请：Tako 帮到主人一次之后（`helped`：答过一句，或把一件托付递回来），按顺序右 ⌥（嘀咕）、贴窗口（嘀咕）、待办和日程（桌面面板一行，只在本机有聊天软件时）。一天最多一样（首次体验那天不再有），每样只出一次，不理就过去；答复下面有一句「要不要记着」还开着时（12 小时内）什么邀请都不出。学过的（`learned` 里有）不教。

原生每次在合适的时刻（启动后 2 秒只看开关、20 秒、一轮做完、离开回来、面板收起、开关变化、模型刚就绪）调 `/ladder/next`，带上只有它知道的：两个开关、本机有没有微信或钉钉（只看应用在不在）、学过什么；`take` 表示它现在能说（没有别的东西占着），这时这句才算出过。页面从 `/state` 的 `ladder.next` 读桌面面板那一行。`ladder.json` 只放阶段、日期、计数和开关。

预先只教一件事：双击它，跟它说话。首次体验那句就是「双击我，说：…」；单击过却从没双击过的人，单击后说一次「双击我，跟我说话。」（回应主人自己的动作，不算当天的邀请）。其余用法用到时才说：说了「这个」没圈时说一次 ⌃；窗口和聊天的空面板只给一个按钮「看看这个窗口，你能帮我做什么？」/「看看这段对话，我该怎么回？」，用过就不再出。文案说主人得到什么、用章鱼的口吻，不出现产品名和技术词（系统设置里的开关名照写；选哪个账号时写账号的名字）。

1. **首次体验**：轮到它时 `Ladder.next` 给一句：本机有聊天软件是「双击我，说：见到某某，提醒我某事。」，没有是「双击我，说：一分钟后提醒我喝水。」。主人当天托付了，见人的那件由 `entrustedSync` 带回下一句（`teach`：「记下了。去打开和TA的聊天看看。」，面板开着就等它收起，最多十分钟），递出就结束；一天没接就放过，不再问。用教学嘀咕同一个泡泡，等答复泡泡、面板、说话都让开才出。
2. **答应过的事**：主人这一轮的话里有承诺，或模型替TA起草的回复里有承诺、追问时，模型在同一轮里用 `entrust ask` 给出要托付的那句、时间或聊天对象和一句短问话，记成状态 `asked` 的托付（同一份记录，`r: entrusted`，不会递出）。答复写完时 `settle_ask` 把问话挂在答复事件上（`ask`，随记录保存），面板在答复下面画一行加「好」；桌面小泡泡把这句接在答复后面。点「好」走 `/entrusted/accept`，说「好」由模型用 `entrust keep` 加那个 id，都变成普通托付。代码兜底：一轮一件；已拿着或问过的同字不问；`quote` 不在主人原话里（草稿的要在这一轮答复的草稿里）就不算；同一段对话主人下一轮说完它还开着就算没理会（`left_unanswered`），连续三次七天内 `ask` 被拒；`entrust quiet` 一直不问，主人自己再托付一件恢复。草稿里的承诺：微信接了本机读取时，点了「好」也先是 `waiting_sent`，现有的草稿发出查看（`_settle_drafts`）看到发出的话里有那句才 `held`，一天没发就取消；钉钉和没接读取的，按主人的「好」算。见人的一件一天以上才递时说「你 N 天前…」（`with_age`）。面板「待办」按 `native_state` 的顺序：有时间的在前（近的先），然后是等人或等地方的（久的先）。
3. **提醒事项和日历**：它是一样邀请（见上），只在本机有聊天软件时出现，桌面面板输入框上方一行「你自己记的待办和日程里写到谁，见到TA、开会前我也提你一句。」加「好」（面板显示后 `/ladder/seen` 记下这一天，当天一直在，过了这天没点就再也不出）；`SystemSources.swift` 只在主人点了这个「好」（`connectSources`）才向系统要权限，拒绝了大脑记下不再提；接上后启动时、存储变化时、托付的定时器醒来时（最多五分钟一次）读未完成的提醒事项和接下来一天的日程，交给 `/ladder/sources`。大脑在内存里用已有的聊天名（微信自己的聊天列表、和 Tako 说过话的聊天、托付里的人，`Chats.chat_names`）比对（`ladder.reminder_items`）：写到某人的提醒变成只在内存的托付（`Entrusted.outside`，`from: reminders`），只等见人，不走转场，不进记录、不进模型记忆、不给 agent 列表；勾掉就不再给，跟着消失；点「✓ 做完了」只记它编号的散列。日程只当时刻：`native_state.wake` 让原生同一个定时器在会前十分钟醒来，`meeting_line` 只在与会者或标题里有某件托付的那个人时递一行「等下要见某某。…」，说的人名取自托付本身，邀请的字不进记录；每个会只说一次。
4. **主人的其他 Agent 和脚本**：不问、不看也不写任何 Agent 自己的文件夹，不为哪一家写分支。大脑每次启动时，主目录里已有 `~/.local/bin` 就在那里放一个三行的 `tako`（`ladder.place_command`：指向 app 里的 `tako_cli.py`，带 `installed-by: tako-app` 标记；已有一个没有标记的 `tako` 就不动；app 挪了位置下次启动更新）。任何 Agent 找 `tako` 命令就能找到 Tako，`tako --help` 写着什么时候用、怎么用（`tako_cli.GUIDE`）。隔离运行只在 `TAKO_HOME` 里面的假主目录里放。Agent 交来的事仍走 `tako entrust` / `tako ask`。

## 主人的其他 Agent

Claude Code、Codex 这类 Agent 替主人派活，走 `agents.py`：大脑启动时写 `agent.json`（端口和一个只给 agent 的令牌，权限 600），`tako_cli.py`（装好后是 `tako` 命令）读它，调 `/agent/ask`、`/agent/job`、`/agent/stop`、`/agent/windows`。这个令牌只开这几扇门，面板的令牌也开不了它们：审批卡片（`/decide`）永远只等主人自己点。

一件转来的事就是一个普通的 `Job`：落在那个窗口自己的对话里（`_conversation_of`，面板上显示「〔Claude 转来〕…」），和主人亲口说的走同一条 `turn`，工具、写权限、发送防线、卡片都一样。不同的只有两处：它的话不进 `said`，所以写外部事项服务仍只认主人在面板里的原话；它不 steer 正在跑的一轮，总是新开一件。结局记在 `Job.answer`、`Job.failed`，结束后保留一小时供 agent 来问。

## 末梢和中枢同权

主人线程的权限和主人平时用的 Codex 一样，这是智能的前提：中枢能读到的，末梢也读得到。沙箱只限制写：

- 读：这台电脑上的文件和密钥配置都读得到，读到的内容发给模型。
- 写：本轮草稿目录（命令在这里跑）和作品目录（`产出文件/` 下，只放成品），加上主人在这段对话里说出的路径（`guards.named_paths`）、拖来的文件（`Companion.named`）和TA说话时所在的 Finder 窗口的文件夹（`_what_it_is_about`，整个主目录和磁盘不算）。窗口和消息里的话进不来。
- 要写别处或出沙箱：模型申请，大多不问主人。改文件先把原件备份再放行（`Hands._backed_up`），普通命令直接放行；只有收不回来或离开这台 Mac 的命令（`guards.lasting_command`）和没说改哪些文件的申请走卡片。批准一次，这个会话里同样的事不再问（`acceptForSession`）。

守住的只有少数底线，都不靠模型自觉：发送永远不按、收不回来的操作走卡片、别人的消息触发的一轮没有工具。

## 任务和窗口

一件事是一个 `Job`（`turns.py`）：谁让做的、在哪段对话、哪个窗口、哪条线程。人和任务是分开的：主人切走、把小章鱼拖走都不影响它，工具没写窗口时用的是任务自己的窗口（`Job.window_id`），不是小章鱼现在在的窗口。结果写回那段对话，面板在别处时显示一行“那边做完了”（`_others`）。它在别的窗口动手（点、填，不算只看一眼）时，那个窗口也显示这段对话（`worked`），除非那个窗口自己的对话后来又有了新内容（`_shown_on` 比两段对话谁更新）；那行“做完了”带主人去动手的那个窗口。微信聊天里交代的事例外：那一行永远带主人回那个聊天，人、回答和草稿都在那里（`Job.goes_to`）；钉钉聊天里交代的回钉钉那个窗口。主人自己点或 ⌘Tab 到它正动手的窗口，小章鱼和面板跟过去，窗口自己跳到前面不算（`Hands._follow_hands`）。面板和停止只管当前对话的任务（`_here`）。

“那边”的每一行，做着的、差一步的、做完的，都能点。点一下就算看过：面板先告诉大脑（`/go`，`going_to`），那行立刻消失，小章鱼落到那个窗口时面板显示的就是这件事的对话，不管那个窗口平时显示哪段（`going`）；以前要等面板恰好挂上那段对话才清，挂到别的对话上那行就一直在。去微信的那一行由原生侧等微信真到前台、主人的手停下再搜那个聊天，主人中途拿走鼠标或切走就不再动，打不开就在面板上说一声。**现在开着的是哪个聊天，只有一个答案**。微信和钉钉同一套（`chats.py` 的 `_confirm` 是唯一改它的地方），面板、开口记到哪、填字放文件前的核对、到场提醒都读它：

- 主人在粘着的聊天应用窗口上一按（或它切到前台、刚粘上），原生侧立刻告诉大脑 `looking`：答案变成“还没确认”。没确认时说的话不记到上一个聊天（开口时 `settle_chat` 当场再读一次标题），到场比对不认任何聊天。
- 还没确认超过半秒（`SHOW_LOOKING_SECONDS`），面板抬头写“正在看…”，上一个聊天的对话藏起来（只藏不清，确认还是它就原样回来，不重画）；半秒内确认就直接从一个名字换到下一个，中间什么都不闪。
- 原生侧在点按后 0.12 秒读第一次，之后每 0.2 秒读一次，两次一样才算画完（微信可能还在画刚点的聊天），最多 2.5 秒；一读到名单里认得的聊天就先发。每次读都是事件触发的一次性调度，不占帧循环，没有定时器。读到的结果带序号（`seq`），走各自的连接可能交错，旧的晚到不覆盖新的；快速连点只认最后一个。
- 3 秒（`LOOKING_SECONDS`）都没有结果，或微信标题一个字都读不出，就是“没认出的聊天”：用这个窗口自己的对话，抬头说“没认出微信里开着哪段对话，照常说就行”，模型被告知没认出、别猜是谁。已经确认过、之后没再点按时，偶尔一次读不出（弹窗挡住）不推翻它；钉钉的辅助功能是准的，读不出名字就是没开聊天。
- 每读一次，原生侧记一行只有毫秒数的日志：`chat wechat since-click=… wait=…（主线程让它等了多久）read=…（截取+识字）settled=… brain=…（大脑匹配）total=…`，钉钉是 `chat dingtalk since-click=… read=… brain=… total=…`。以后再慢，看这一行就知道卡在哪一步。

标题对名字的规则（`_candidates`）：先找名单里一字不差的（第二候选读对了也算）。近似只在名字至少 4 个字、只差一个字（错、漏、多一个）、数字完全一样、而且在微信自己的聊天列表里只有这一个这么接近时才认；更短的名字、含“、”的标题只认一字不差。都不是就当作“只知道标题的聊天”（`_by_title`），不认成别人。重名时取微信聊天列表里有的那个，有几个就取最近有动静的（`_pick`），不读消息库。聊天列表、没起名的群都只在第一次当场读，之后变了在后台重读、先用手头的（`_kept`）。跟随聊天无需解密消息分片。粘上微信时就在后台把名单和聊天列表预备好（`_warm`）。往微信填字、放文件前后，“开着的是不是它”用同一个答案判断（`is_showing`）：标题是名单认得的聊天，就只认那个聊天的名字，不再退回简称规则，避免把单聊的文件放进群聊。

没起名的群，微信标题是其他成员的名字加人数，太长时截断，名单里只有群号：按联系人库的成员表认（`wechat_reader.unnamed_groups`、`guards.group_by_members`）；没有人数时要所有成员都在标题里才认，认不出就是只知道标题的聊天，绝不是某个成员。读标题时搜索框左边当作聊天列表丢掉，这条边每个微信窗口各记各的（`listEnds`）：单独弹出的聊天窗口没有列表，用主窗口的边会把整个标题当列表扔掉。实在认不出的标题也不留在上一个聊天：换成一段只按标题命名的对话（`_by_title`），聊天记录读不到就如实告诉模型。

钉钉走同一套：每个聊天一段对话，主人切到哪个人，面板就显示TA在那个人那里和 Tako 说过的（`follow_dingtalk`，键是 `dingtalk:` 加聊天名）。钉钉经辅助功能暴露完整界面，不用截图识字（`DingTalk.swift`）：聊天区是 `ChatSplitView`，顶部一行是聊天名，消息是一个表格，每条消息从发言人头像开始（贴着聊天区边上的方形图），主人自己的在右边、下面还有已读回执，别人的在左边；群里别人头像右边紧挨着的小按钮是名字，旁边是这条的时间；整行宽的是时间行；卡片的几行字、文件、图片合成那人的一条。粘着时主人在钉钉里点按、或切回钉钉，先告诉大脑 `looking`，0.12 秒读一次聊天名（读到就说，同一个也说，好让点在聊天里面不算换人），0.6 秒再读一次并且读不到也说（`followDingTalk`），和微信走同一个 `_confirm`；主人开口时 `settle_chat` 再确认一次，读不到就用这个窗口自己的对话，不记到上一个聊天。钉钉只按名字认聊天，两个同名的钉钉聊天会是同一段对话。消息只在主人开口时读窗口里看得见的那几条（`chatMessages` → `_dingtalk_since`），钉钉显示的已不是这个聊天就当读不到；交给模型过的那几条在内存里按指纹记住，下一轮只给新的。钉钉改版读不到时静默不匹配、如实说读不到，不退回截图。

动手默认在后台（`Operate.swift`），主人的焦点、鼠标、剪贴板都不碰：

| 动作 | 后台的做法 |
|---|---|
| 点 | 辅助功能的按下（`pressBehindTheOwner`） |
| 输入 | 直接写进字段（`insertBehindTheOwner`），写不进才按键发给那个应用 |
| 填网页 | Chrome 里从页面内部填（`webfill`）：普通框和框架受控的框走元素自己的 setter 加 input 事件，富文本编辑器（Lexical、ProseMirror 等）选中后收一个带文字的粘贴事件，读回核对才算填好 |
| 按键 | 只发给那个应用（`postToPid`） |
| 滚动 | 把下一个看不见的元素滚进来（`scrollBehindTheOwner`），滚完核对真的动了 |

网页上传文件也从页面内部做（`Hands._upload_page`，GitHub issue 3）：点上传按钮会打开系统的文件选择框，后台选不了，所以不点它，找到按钮那一块里的上传框，文件分块（每块约 1.5 MB）作为数据传进页面，拼成文件交给上传框，发出它听的 input 和 change 事件；上传框要点了按钮才出现时，点那个按钮，同时拦下它要打开的选择框。文件离开这台 Mac，所以一件事里第一次往一个网站传，卡片列出文件和网站等主人点头。交进去后读页面看有没有文件名、进度、“上传中/成功/失败”，说不准就让模型看窗口，不说传好了。`operate_window` 点开了选择框，就按它自己的“取消”关掉并告诉模型这条路。

网页的输入框不靠辅助功能：它写不进富文本编辑器，发给后台浏览器的按键也没人收。`fill_input` 遇到浏览器窗口就用 Tako 自己固定的一段页面代码（文字以 base64 作为数据传入，不点、不按键、不碰剪贴板、不提交），经 Apple 事件在那个窗口的当前标签里跑，分几次调用：页面代码和页面自己的脚本隔开，拿不到 promise 的结果，编辑器要过一会儿才认新的选区。主人没开 Chrome 的「允许 Apple 事件中的 JavaScript」或系统没允许 Tako 控制 Chrome 时，回到原来的填法并告诉模型差哪个开关。第一次控制一个应用时系统会弹框问主人，回话前脚本一直卡着，所以原生侧先问一句能不能控制（`mayControl`，不弹框），要问就把系统的框放出去、这一步立刻返回。有的按钮只认真人亲手点（人机验证），后台点了没反应就如实交给主人，不绕过、不再点：后台点过的页面可能卡在提交中，主人亲手点也没反应，所以先重新载入那个标签、重新填好，再交给主人。

Chrome 要先打开它的辅助功能才看得到网页里的东西（`askForAccessibleContent`），第一次要等网页真的进来，否则第一眼按不到网页里的东西。它不画被自己窗口盖住的窗口，所以后台时先在应用内部升上来（`surface`），盖在上面的别的应用不受影响；被别的应用盖住时它照常工作。主人正在同一个 Chrome 的另一个窗口里、它完全盖着目标窗口时不能升（会盖过主人），`look` 如实说看不到，主人回到那个窗口再接着做（`coveredByItsOwn`）。

最小化或隐藏的窗口截不到：ScreenCaptureKit 不回话，`Hands.shot` 等 3 秒就放弃，告诉模型。别的桌面上的窗口截得到，但辅助功能看不到它，`look` 会注明只能看。

主人指的是窗口背后的东西，不是那张图：先落到实物上，再一层层往下走，走不通才说。Finder 窗口落到真实路径（问 Finder，不行就用 Spotlight 加窗口里列的文件认出是哪个同名文件夹）和选中的文件，文件的事用命令做。标字（`point`）先看截图，再问页面（屏幕外的内容滚过来；位置问字本身（`AXBoundsForRange`）：Chrome 给元素的框只算露出的部分，长段落露一截就像看得见，屏幕外的还会压扁在页面边上。滚不到就不画圈，直说），最后才容错匹配，数字不容错。标了但窗口不在前台，主人到了再标一次（`_point_when_back`）。同一个工具同样的失败第二次，模型会被告知别再试（`_once_is_enough`）。

末梢和中枢要同等水平：同一个模型和强度（`effort` 不写死，跟主人的 Codex），同一个交付标准（提示词要求读全材料、核对成品），不靠操作窗口取材料。主人把小章鱼粘在窗口上，就是为了不占前台也能把事做完，所以“切到那个窗口”不是流程里的一步，核对成品也不该弹卡片或打开 Word（`look_at_file`）。要的东西先落到实物：聊天记录和收到的文件走 `read_wechat`（文件带本机路径，`wechat_reader.received_file`，没下载的如实说），文档走 `look` 的“文件”路径。

拖动、双击、后台滚不动的地方、微信的输入、递文件要真键鼠。把带窗口号的滚轮和点击事件直接发给目标窗口时，微信、WPS 都不动，自写的窗口也只收到事件不响应，所以这条路不通。`ownerSettles` 只在主人恰好在这个窗口时用真键鼠：窗口在前台只是手在动就等几秒，不回去问模型。否则 `waitForFront` 说明是哪一种原因（`not_front`、`covered`、`hand_moving`），工具告诉模型别让主人切窗口，换条路或做完其余。这一轮结束后 `_pick_up_when_back` 悄悄盯着那个窗口，主人哪天自己切过去就接一轮，面板只说不用专门切。主人说了别的话就取消；窗口在前台却还是做不成，接两轮就放下，不再花模型调用。

填入和递文件内容是确定的，不用模型接：`_hold_fill` 记下这一步，回复模型“已排好”，`_place_when_back` 盯着目标窗口。主人切到那里，软体跟过去（`followTo`，不动任何窗口），手一停就由程序放好，放之前重新核对微信打开的是哪段对话；原来开着的面板等放完才跟过去，也不抢键盘（`followDone`）。每个去处各排一条（`_fill_key`：对话加上给谁），给同一个地方再调一次替换排着的，给不同的人各排各的，到了一条接一条放（`placing`），每条开自己的聊天。主人接着说话时模型会被提醒，要不要就由它传 `cancel`。微信标题对不上要放的那段对话时，先在搜索框里打开它，再看标题：刚打开的标题还没画完会被认成乱码，所以看三次；有联系人库时，只有标题读成另一段已知对话才不放，没有库就不放。窗口没了、搜不到人或等了半小时，都告诉主人并给出文件。按给后台应用的 Cmd+V 不生效，所以微信的粘贴只能等前台。

## 主人指给 Tako 看

主人按住 ⌃，在粘着的那个窗口上用鼠标指（`Pointing.swift`）。只认这个窗口、只认单独的 ⌃，别处和别的组合键一律原样放给应用；代价是这个窗口里 ⌃+点击不再是右键，触控板两指点照旧。

- 按在字上拖：把按压去掉 ⌃ 原样交给应用，由它自己选字，松手后从焦点元素读出选中的字和位置（`AXSelectedText`，网页用 text marker），读不到就读窗口上那一条。
- 别处拖、画一圈：圈住拖过的范围。只圈住一样东西就当那样东西；在一张大图上圈一小块是“图片局部”，带上在图里的位置和圈里的字。
- 点一下：辅助功能找到下面最近的链接、图片、按钮、输入框、段落或条目；什么都找不到（微信）就取按压处同一种颜色的那一块（气泡）并识字。再点同一个就取消。

要快：墨圈在松手那一刻就画，用按住 ⌃ 时提示框已经查到的东西，后面再补里面的字；按下 ⌃ 时先拍一张窗口，松手后只识圈里那一小块（实测辅助功能 1–50 毫秒，整窗识字 1–6 秒，只识圈里 0.2–0.5 秒）。

圈不是截图，是手指：指的那一刻就落到实物上（链接地址、图片地址、文件路径、所在文档、字），因为TA说完话前页面可能已经滚走。墨圈用 `Enchant.circle` 同一种笔画，带编号，留到发送时飞回小章鱼；滚动就淡掉，面板里的块还在。面板把块和话一起交给 `/ask`（`points`），大脑把它们作为“只是材料”放进这一轮（`prompts.pointed_at`），指到的文件和所在文档可写，和拖进来的文件一样。

## 一轮卡住时

常驻线程会越来越重。主要不是字，是窗口截图：一张只占很少 token，却有上百 KB，断线重连后要全部重传。所以每条常驻线程各有两条线（`_compact_if_long`）：token 到 `COMPACT_AT`，或截图到 `COMPACT_PICTURES_AT`，就压缩。

压缩在这件事结束之后才开始（`job.ended`、面板已显示答完）。它占着那条线程的锁，所以两边不会同时往一条线程上发：压缩期间主人在这段对话再说一句，立刻走触手（`summarizing`），带着这里说过的话；压缩完，常驻线程下一轮听到触手做了什么。下一句先到（比如 steer 没送进去、紧跟在后面的那件），它先用这条线程，这次压缩就不做了，这一轮结束再看要不要压。

一轮等模型时，Codex 自己会重试，也会把连接换成整包上传的 HTTP。Tako 不替它重试，只做三件事（`_finish`）：

- 把重试原样告诉主人（`trouble`），面板不再显示上一步。
- 重试不算有进展，不重置 15 分钟的静默上限。
- 线程已经很重、又连续传不上去时，停掉这一轮，下一句换轻线程（`_leave_thread`），带上这个窗口最近说的话。不重放，避免把做过的事再做一遍。

一轮进行中主人又说话：同一段对话里干活中途说的话，带不带文件、圈选，都是这件事的补充，由 `_ask` 在这段对话的锁（`joining`）里交给 `_join`，不另开一件、不排队、不加等待：

- 这一轮在跑：`_steer` 用 `turn/steer` 送进去。文字前标「第N条」，文件给路径，图片走 `localImage`，圈选用 `pointed_at` 的文字（圈本身不带图，和一轮开始时一样）。
- 这件事还在准备、提示词没定（`Job.sealed` 之前）：放进 `Job.later`，第一轮就带着全部各条一起开工；提示词定了、轮次还没开始，等它开始（`Job.live`）再 steer。
- steer 没送进去（那一轮刚结束，或办公智能体不能 steer）：同一段对话里所有还在等的话并进紧跟在后面的那一个 `Job`，一轮做完。
- 写权限在一轮开始时定死：中途才交来、这一轮不能写的文件记在 `Job.late`，真要写它时走平常的批准卡片（`Hands._late`，理由「这一轮开始后才交来的文件」），不另开一件；下一轮起它就和开头交来的一样可写。

面板给这件事一张清单（`Job.items`，快照里的 `items`，答复事件里带着同一份、记进记录）：每条话一行，追加的立刻进来标「收到，会一起改」；模型接着动了变「在改」；模型中途的进度行和最后的逐条回执（行首「第N条 改好／没改／要你定：一句」，`receipts`）定每行的状态，冒号后那句做那一行的副文字，回执没提到的行不标状态。有清单时答复正文去掉清单已经说了的行（改好、在改、并入，`without_listed`），只留总述、没改的原因和要主人定的；桌面小泡泡的长短也按去掉之后的正文判断。改口、撤回是用自然语言说的，是不是改口由模型判断：它回执「第4条 并入第3条」，这句就不占行（`shown_rows`），结果写在第3条上；模型没这么说，就照新的一条。代码里没有关键词规则。只有一条话时不出清单。不加按钮、不加批量模式。桌面小泡泡里（`asideNews`），中途说的话标着 `joined`，泡泡显示「收到，会一起改」再接着这件事的进度，最后只有一份答复。

别的窗口说的话不并进来：它有自己的线程，关掉开关时大脑忙就开触手。其他 Agent 转来的事照旧总是另开一件，主人的话也不并进还没开始的转来的事。

## 办公智能体当大脑

只装了 WorkBuddy、Qoder 或千问办公时，可以用它们自带的命令行智能体，走它们已有的登录和积分，不装 Codex。上面的一切照旧讲 Codex：`office.py` 的 `AcpRuntime` 把线程、一轮、事件和审批请求翻成 ACP（Agent Client Protocol）。

- **只有 Tako 的工具。** 智能体启动时关掉它自己的全部工具（Qoder 用 `--tools`，WorkBuddy 按名字全列进 `--disallowedTools`，因为它的 `--tools` 不起作用），只留网页搜索；它的生图、视频、发消息、命令、写文件都没有，和 `BRAIN_CONFIG` 关掉 Codex 的插件一样。还有漏网的会来请求许可，`AcpRuntime.permission` 只放行 Tako 的工具和网页搜索。每个智能体进程有一个看门的小进程，大脑一走（哪怕被强杀）就结束它：WorkBuddy 的智能体输入关了也不退出。
- **Tako 的工具经 MCP 到它手里。** 每段主人的会话带一个 `tako_mcp.py`，它把调用经本机通道送回大脑，大脑像回答 Codex 一样回答（`Hands._tool`）。一次性线程不带它，智能体也不留任何工具，所以读到的话什么也动不了。
- **命令和改文件是 Tako 的。** 智能体自己的命令不进沙箱，所以关掉，换成 `codex_tools.py`：同一种沙箱、同样的审批、同样的备份和卡片。
- **一个提示词一个进程。** ACP 的系统提示是进程级的：所有主人的线程（每段对话的常驻会话和触手）共用一个进程（提示词相同），每段对话就是这个进程里的一个会话，开场白、笔记这些一次性线程按各自的提示词各一个，用完让它删掉会话（Qoder），WorkBuddy 不存会话，在 Tako 自己的文件夹里跑。
- **插话并进下一轮。** ACP 不能把话送进正在跑的一轮（`turn/steer`），所以中途说的话并成紧跟在后面的一件，一轮做完。压缩由智能体自己做。
- **登录。** 读它们放在磁盘上的登录（WorkBuddy 的到期时间、Qoder 的 `status`），不花钱；一轮被它以登录为由拒掉，面板就说那一件事：打开一次那个应用，再点“再试一次”。用的模型就是那个应用里设的，Tako 不另设。

`Companion` 由 `Chats`、`Turns`、`Hands`、`Lectures`、`Agents` 五部分组成，共用一份状态，字段都在 `tako_server.py` 的 `__init__` 里写明了用途。每个任务自己的状态在 `Job` 里。

## 说话、托付与教学

说话键 `Speaking.swift` 在现有辅助功能事件监听中识别单独按放的右 ⌥，左 ⌥ 和右 ⌥ 的组合键照常透传，并保留 ⌃⌥T。首次开始说话才请求麦克风及语音识别权限；`SFSpeechAudioBufferRecognitionRequest` 强制本机识别（`requiresOnDeviceRecognition`，`taskHint = .dictation`，自动加标点），音频缓冲只存在内存。识别语言按主人的首选语言顺序取 Speech 自己列出的写法（`SpeechLocale`，`Heard.swift`：zh-Hans-CN → `zh-CN`，不是地区格式的 `zh_CN`），取第一个这台 Mac 能本机识别的；一个都没有时泡泡变输入框，说明要在系统设置的听写里装好语言。其他应用也可以使用右 ⌥，Tako 不修改它们的快捷键。

按说话过程中的先后顺序：
- 按下右 ⌥ 的同一刻泡泡出来，写「马上好，先别说…」，音量条灰着跑一道光；麦克风真正开始录（`engine.start()` 之后）才换成「在听」。已授权时不再等授权回调，下一轮事件循环就开引擎。
- 在听：五根音量条随声音跳（`ListeningLayout.level`，安静时也有一道慢波，看得出它还在听），下面是到目前为止听到的全部文字（`Heard`：本机识别停顿后可能从头再给，之前的字留着接上，最终结果又给全了就以它为准），泡泡宽度固定、随文字长高，最多五行，再多保留最新几行、开头一个「…」（`ListeningLayout.fit`）；最下面一行小字「再按一下右 ⌥ 结束 · esc 取消」。
- 没有字时的灰字只说真会发生的事：开始是「说吧，字会出现在这里」；有声音 2.5 秒仍没有任何字（`Heard.late`，这台 Mac 的识别把字留到最后），改成「在听，说完了字一起出来」。
- 身体不伸手也不鼓包：`Goo.earTo` 指向泡泡，眼睛看着它，整个轮廓随音量均匀放大最多 5%（`Goo.earSwell`，在 `target` 里统一缩放，形状不变），在听时不朝光标鼓；不画肢体、不加描边、不加五官。只在说话期间运行，靠说话时本来就满帧的帧循环（`Speaking.track`），不另设定时器。
- 再按右 ⌥：写「听到了，交给 Tako…」，等识别收尾（已有字时最多 1.5 秒，一个字都还没有时最多 4 秒）；说话过程中没出过字的，最终的整句先在泡泡里停 0.9 秒给主人看到，再交出（这期间又按右 ⌥，这句马上交出，不丢）。然后交出，都走面板的 `sayFromKey`，和在面板里打字完全同一个发送（同一个 `/ask`、同样带上画的圈和拖来的文件、发不出去时字放回输入框），这句话是那段对话最新的一条，面板里打了一半的字保留。交到哪里看形态（`ReplyLayout.answersAside`）：贴着窗口，泡泡收起，`Controller.sayInPanel` 打开那个窗口的面板；面板本来开着，就在开着的面板里；只有在桌面（没贴窗口）且面板关着时，面板不打开，答复回到这同一个泡泡（见下面「答复在泡泡里」）。
- 听的时候直接打字：停止录音，已听到的字和首键一起进泡泡里的输入框；回车同样交出，去处同上。
- 诊断：每次说话结束（交出、取消、改打字、出错）往 panel.log 写一行，只有数字和固定词：`speech locale=zh-CN ondevice=1 ms=… buffers=… loud=… first-voice-ms=… first-partial-ms=… partials=… resets=… final=0/1 chars=… error=<domain>:<code>|none end=done|waited|cancel|typed|fallback`。`buffers` 是交给识别器的音频块数，`loud` 是有声音的 50 毫秒片数，`first-partial-ms` 是第一个中间结果离开录音的毫秒数（`-` 表示整段没有中间结果），`chars` 是最后字数；听到的字不写。识别器不可用、麦克风打不开也各有一行固定词。
- 收尾：esc、打字泡泡失去焦点、60 秒没有声音和输入、没听清（少于两个字）、麦克风还没开就又按了一下，泡泡都先用一行字说为什么，再淡出；不留悬着的泡泡。系统不支持本机识别、没授权或麦克风不可用时，泡泡变成输入框，提示「…打字跟我说吧。」，识别中途出错时已听到的字留在框里。大脑没接住（`/desktop` 失败）时字回到输入框，按回车再试。

答复在泡泡里。只在桌面且面板关着时：
- 一条路：`SidePanel.sayAside` 先切到桌面对话（`openDesktop(show: false)`，同一个 `/desktop`，面板不长出来），再调 `sayFromKey(text, true)`。面板页面本来就在后台按原来的节奏读 `/state`，`side.html` 的 `takeAside` 从同一份状态里读出这句话之后的进展（`asideNews`：按时间认出主人刚说的那一行，再取它之后 Tako 的第一条答复），用 `{aside: …}` 告诉原生侧。泡泡不另存内容、不加接口（大脑只多认一个 `replying` 字段，见下）、不叫模型、大脑不为它多写一个字。
- 泡泡还是说话的那个窗口（`Speaking.showReply`，同样的墨边、宽度和字体）：上面一行灰字是主人刚说的那句，下面先是「收到，在想…」，做事时换成面板自己的那行进度（最新一步、连模型不顺的那句，或面板的「Tako 在想…/在动手…」），答复到了换成答复。进度只挂 6 秒，之后泡泡收起，身体上已有的在想/在干活样子接着表现（页面照常 `tellGoo`），答复到了泡泡再出来；进度来了不会把收起的泡泡再叫出来。
- 长短（`ReplyLayout.judge`）：页面先把答复转成泡泡里的纯文字，并标出有没有面板才画得好的东西（`asidePlain`：列表、代码、表格、标题、链接、图片、文件；文件写成「名字（在 所在文件夹）」）；原生侧用泡泡自己的字体和宽度量行数。没有这些且不超过两行是短答复，整段显示，按字数停 4 到 8 秒（`4 + 字数/10`）；否则是长答复，显示前两行加省略，下方小字「展开 · 双击我也行」，停 12 秒。指针停在泡泡上不淡出，离开后 1.5 秒再淡出。淡出等都是一次性调度（`stay`，按 `replyToken` 认是不是同一次），没有定时器；答复停着时不跑帧（`Speaking.animating` 不含它），身体动了帧循环本来就在跑，顺手把泡泡跟上。
- 点泡泡或双击章鱼：桌面面板从身体长出来，页面把这条答复（按它的时间 `data-at`）滚到可见处（`setOpen` 里的 `asideAt`）；面板一打开泡泡就收（`open` 消息里 `speaking.endReply()`）。淡出后内容照常在面板和对话记录里。
- 需要主人处理的不进泡泡：确认卡、这句之后出的错、发不出去（`/ask` 失败），页面让原生侧先摆好桌面面板再打开（`openAside` → `showDesktopPanel`），和原来一样。停了且没有答复，进度泡泡收起。期间面板换到了别的对话（比如主人把章鱼贴上了窗口），泡泡不再接这段对话的消息。
- 泡泡在时再按右 ⌥：泡泡直接换回「在听」，交出后仍进桌面这段对话的常驻线程。esc（照样传给前台应用）或按在泡泡和身体以外的地方（`Speaking.pressed`，读现有事件 tap 里的按下位置）收起泡泡，正在做的事不受影响。
- 禁言时答复照常进泡泡（这是主人自己问的），不加任何额外动作；Tako 本来就不出声。
- 与提醒泡泡不重叠：答复泡泡在的时候，`Entrusted` 的检查带上 `replying`，大脑把它当成「有事在做」（`busy`），已经举着的提醒收回、不记没理会，新的不递；任务结束这个转场机会留到不忙时再用（`entrusted.tick` 只在不忙时清 `completed`）。泡泡收起（`endReply`）时叫醒一次检查，提醒接着出来。
- `hidesOnDeactivate = false` 等浮窗设置都在 `BubbleLayout.prepare`，说话、提示和答复共用这一个窗口；答复时它是不激活应用的面板，点它不会把主人的应用换下去。

面板出现和收起：卡片从身体所在处长出来——`Controller.tellOrigin` 把身体在面板页面上的位置告诉 `setOrigin`（页面把它夹到卡片自己最近的边上），`#card` 以那里为原点从一小团墨似的圆，0.32 秒涨过一点再回弹到原位，内容一直在里面；收起时 0.22 秒反向缩回那里，原生窗口 0.24 秒后才放掉。贴窗口和桌面面板是同一套。身体同时挤一下（`kick`）并看向面板（`lookAt`），不伸肢体。位置在摆放面板时告知，以及帧循环里身体挪动后最多五次一秒；帧循环只在有东西动时运行，没有为它设的定时器。切到另一段对话再打开（桌面面板、历史）走 `openFresh`：先读一次那段对话，再长出来，不先空后填。

桌面面板（抬头「Tako 在这里」）：
- 是普通层级的窗口（`placeSide`），主人去别的应用，那个应用的窗口照常盖过它，和贴窗口的面板一样；以前每帧把它提到浮动层，盖住所有应用。被盖住时双击小章鱼把它提上来（`desktopPanelCovered`），没被盖住才是收起。
- 窗口就是卡片加右边的拉宽把手那么宽，整块都接点击（`HandHit.panelLetsThrough`）。贴窗口的面板窗口比卡片宽，只有卡片接点击，靠帧和指针事件随时改；桌面上身体静止时没有帧，以前这样会把输入框停在「点击穿过去」上，点了打不了字。打开时网页是第一响应者（`makeFirstResponder(web)`），`panel.log` 记一行 `desktop panel open key=… responder=… active=…`（只有数字和固定词）。
- 身体坐在它左上角，和贴窗口时在面板抬头左边同一个位置（`PanelPlace.seat`，`Goo.seat`）：弹簧拉住、不受重力，也不算落地（`settled` 是站在地上，腿、影子和伸手的休息位置都画到地面：算了就被拉成一根长杆）；先收拢、收回手（最多 0.4 秒）再整个过去，速度有上限，`Tako --seat-check` 离屏量各种起始状态下皮肤、腿、手离身体多远。游走、跳、偷看、摊开、睡觉、伸手够指针、闲时场景都不做；收起后照常。打开时 `orderFrontRegardless` 出现在最前一次。按住抬头拖动（`moveStart` → `movePanel`，每帧跟指针，夹在指针所在屏幕里），身体跟着走；这次运行里记住最后的位置（`desktopLast`），不写偏好。抬头右边有收起钮，网页有焦点时 esc 也收起；收起只是藏起来，再打开（`openHere` 不再问 `/desktop`）还是原来那段对话和位置。
- 开着时把小章鱼拖走，面板像贴窗口时一样先收起；放到窗口上，面板以那个窗口自己的对话再打开（`reopenOnStick`），放在桌面上就收着。粘上任何窗口都先把面板交给那个窗口（`PanelPlace.stuck`），并重新告诉大脑贴在哪里，哪怕是上次贴过的同一个窗口：以前 `reportStuck` 在面板还算桌面的时候什么都不说，同一窗口同一标题也不再说，面板就一直是桌面那段对话。

`--showcase-frames` 出「马上好」「在听（安静）」「在听（有字）」「在听（音量最大）」「在听（字留到说完）」「很长」「交出」「没听清」以及贴窗口在听的帧，答复留在泡泡里的「进度一行」「短答复」「长答复带展开」（`38-reply-step`、`39-reply-short`、`40-reply-long`），另有面板打开时挤一下在变形最大那一刻的帧（`36-squeeze-widest`）；加 `--showcase-panel=<页面地址>` 时，再用不显示的 WKWebView 画说完后桌面面板从身体长出的中间一帧和展开完成一帧，以及点开长答复后面板定位在那条答复的一帧（`41-reply-expanded`）（页面来自一个临时 `TAKO_HOME` 加假 Codex 的大脑，不截屏）。加 `--showcase-walk=<步骤.json>` 时只出走查要的帧：每一步是身体加上那一刻主人面前的东西——桌面面板（`panel` 是页面地址，`js` 先在页面里跑，模拟原生告诉页面的开关、学过什么、手里拿着什么）、身体旁的一句（`hint`）或举出的一件（`carry`），同样离屏、不截屏、不问系统。

`entrust` 可在主人那一轮带 `variants`：推迟或忽略后的递回按次数取下一句并追加到同一记录，缺省使用原话。身体通过递回次数变化手的动作；禁言时不递也不演。面板从现有托付运行态显示待办，按钮调用同一个结局接口并同步系统通知。

托付记忆进入提示词最多 12000 字，优先列最近仍拿着的事项，再列最近八件结局，并汇总每件最多八次记录中的回应；超出时提示模型通过 `entrust list` 查询全部。完整记录仍只在原来的每日文件里。

到点显示、工具回复、当前时间提示、命令进程的 `TZ` 和记录按天分组，均使用主人配置的时区，未配置时使用系统时区。

轻量提示 `Teaching.swift` 不自己决定说什么：问大脑的 `Ladder.next`（见「主动性的梯子」），离开后回来（`Attention` 告知）、一轮结束后、面板收起后，且空手、未安静时才说，经 `Attention` 检查前台窗口的全屏标记但不取标题和内容；不设定时器。文件预览遇到受保护文件夹的读取拒绝时，面板可打开系统的文件与文件夹设置；系统询问仍由实际读取触发。

教学嘀咕复用说话泡泡窗口，显示时换成不接收鼠标、不激活应用的轻量画法；主人开始说话时先收起提示。等待主人到场时，`back_watch.py` 只在有订阅者时启用原生观察；应用激活及鼠标点击后通知它，五秒一次检查作兜底，最后一个订阅者退出时停掉。窗口因其他原因改变焦点时目前靠兜底发现。

桌面对话向上翻时，`records.conversation_before` 每次从同一份每日记录读出更早的一天；旧事件只在面板中呈现，不插入正在运行的事件队列。快捷回答携带原对话的本机键，点击时用原记录恢复该对话。

闲时动作 `GooIdle.swift` 只用身体、已有光标位置和本机固定图形；自主动作在空手、未安静、空闲且附近没有窗口时稀疏轮换，举手时碰到手可击掌；持有托付或递回时动作让路。新动作只用身体形变、眼睛和墨来演，不添加五官或描边。文件读取实际报错含受保护目录与 Operation not permitted 时，普通命令和转换进程复用同一张文件权限提示，不预检文件夹。

点小章鱼本身：判断在 `HandHit.swift` 的 `Taps`，用真实时钟（身体的 `clock` 停帧时不走）和系统双击间隔 `NSEvent.doubleClickInterval`。单击马上有反应，只用身体、眼睛和墨（`Goo.poked`：按下去一个凹、弹一下回头看、蹦一下、伸个懒腰往上看、喷一小股墨，不连着两次一样），不开关面板；第二下落在双击间隔内就开或关对话面板（`Goo.openOrClose`：贴着窗口是那个窗口的面板，在桌面是身边的桌面面板，`learn("open")`）。1.4 秒内第 4 下坏笑警告，第 5 下喷墨逃走：一次双击再手滑多点一下（3 下）、开了马上关（4 下，只坏笑）都不会喷墨。面板开着时按下不再先关面板，真拖动起来（移动超过 4 点）才关，所以单击不会把开着的面板关掉。从没双击过的人单击后，过了双击间隔还没第二下，就用同一套教学嘀咕（一次运行一次、自己消失、有事时不出）说「双击我，跟我说话。」；双击过就再也不提。提醒泡泡的按钮、拖拽、右键菜单、⌃ 指点不经过这里。

点程序坞图标会解除隐藏，让身体游到前台窗口旁或光标附近，保持自由状态，不打开面板；手动禁言继续生效。程序坞菜单沿用小章鱼菜单的状态，另提供「贴到当前窗口」。原有 ⌃⌥T 和更新面板仍用原来的 `summon()`，保留贴窗口并打开面板的行为。固定教学清单记录程序坞入口是否用过。

## 定时器与回调

常驻开销的规矩：身体不动就不画，没有要等的事就不设定时器。

**帧与节奏（`Controller.advance`、`pace`；`Goo.pace`、`nextEvent`）。** 显示回调只在有东西在动时运行：被拖、游走、演场景、泡泡伸出收回、窗口在动、主人按着 ⌃ 指、说话气泡、在干活，按原来的 120/60 帧；只有眼睛跟光标或眨眼时 30 帧。其余时候回调暂停：
- 静止（自由状态站着、睡着）：没有任何帧。呼吸（表皮、高光、亮边，睡着时还有小嘴开合）、梦里的 Z 和鲸鱼娘的睡泡泡交给 Core Animation 按同样的公式循环，限 15 到 30 帧，表皮在此期间屏住呼吸（`breathHeld`），交回时从 Core Animation 走到的那一口气接上。
- 慢节奏（贴在窗口上）：每秒 3 次一个轻量帧，让触须随窗口边轻摆；身体、脸、装扮、腿凡是输入没变的部分都不重画（`bodyKey`、`faceKey`、`costumeKey`、`armsKey`）。鲸鱼娘的尾巴摆动、拿着东西或举着提醒时那只手的波纹，同样交给 Core Animation（`keepWagging`、`keepRippling`）。再次举出的提醒会上下晃，用每秒 30 帧；自由状态下举着（有腿要合并）每秒 12 帧。
- 身体自己排好的下一件事（眨眼、看一眼窗口、散步、入睡、柯基抖耳朵）到点前一刻恢复帧；期间的时间由 `fastForward` 跳过，不逐步模拟。
- 恢复帧的触发：指针在身体附近移动、按下鼠标、在睡觉时任何移动（会把它吵醒）、或移动大到眼睛看得出要转；主线程上任何事做完（命令、回复、网页消息、通知）后，`watchForWork` 发现身体有了要动的事。远处指针移动只更新点击穿透，不唤醒。点击穿透（`updateClickThrough`）在每帧和每次指针事件上都更新，所以停帧时泡泡按钮照样点得到。

**空手、没贴窗口、没在演时仍在的定时器和回调。**

| 名称 | 频率 | 理由 |
|---|---|---|
| 眨眼、散步、闲时动作、入睡的到点唤醒（`Controller.schedule`） | 一次性；醒着约每 2.4 到 6.5 秒一次眨眼，每次约 0.3 秒、30 帧 | 这是身体本来的动作；睡着时没有 |
| 取命令长轮询（`Hands.pollCommands`） | 空闲时大脑每 20 秒空返回一次 | 大脑交代事情的唯一通道，本机 HTTP |
| 权限开关复查（`Permissions.lookAtSwitchesSoon`） | 两项都开后每 30 秒；辅助功能没开时每秒，录屏没开时每 2 秒（只看；系统的询问等轮到那一步才出） | 系统的改动通知不一定到，开关被关掉要知道 |
| 更新检查（`Update`） | 每 6 小时 | 发版靠它送达 |
| 全局事件监听（`Pointing` 的事件 tap、`watchForWork` 的指针监听） | 随键鼠事件 | 指给 Tako 看、说话键、唤醒；不另要权限 |
| CoreAudio、CoreMediaIO、应用切换、Space、睡眠唤醒的通知（`Attention`） | 随事件 | 安静状态由系统告知，不轮询 |
| 主线程空闲前的观察（`watchForWork`） | 主线程每醒一次看一眼，约几微秒 | 停帧时别处改了身体要马上恢复 |
| 离开检测（`Attention.watchAway`） | 只在拿着事或还有一句没说出口时，最多每 2 分钟一次 | 判断主人离开后回来 |

另外：拿着事时托付有到点定时器、3 秒（举着泡泡）或 30 秒（只是拿着）的兜底检查；说话时有一秒一次的空闲计时；答复在泡泡里时只有一次性的淡出调度，不跑帧；贴在微信上时主人点按后读顶部条，贴在钉钉上时主人点按后经辅助功能读一次聊天名（两次一次性延时，不轮询）。

**测量。** `TAKO_PACE_LOG` 让一份隔离运行的副本每 5 秒把帧数、主线程各部分耗时和唤醒原因写进 panel.log，并且不注册 ⌃⌥T、不装 ⌃ 和说话键的事件 tap、不写主人的偏好设置，免得和正在用的正式版抢；可加 `free`（以宠物状态开始）、`alone`（身体看到的指针固定不动，点击仍按真指针）、`nolog`（只保留这些保护、不计数）、`nobreath`（不交给 Core Animation，作对照）。

## 隔离运行

设了 `TAKO_HOME`，所有状态都写到那个目录，回传也关掉。原生 app 和大脑都认它，正式版绝不能设。

```bash
open -n dist/Tako.app --env TAKO_HOME=/tmp/tako-test --args --selftest
```

面板打开时可能挪动真实窗口，自测不会打开面板，也不检查更新。`scripts/showcase_strips.py` 仅供开发验收，需安装 Pillow。

## 记忆判断与本体

`ontology.py` 的 `Memory` 独立于 `Entrusted`。`memory_forever` 只在模型就绪且没有主人任务、记录写入结束时检查本机痕迹，有新增才调用 `_reader`（原有无工具线程）；失败不推进读取位置，退避五分钟。模型拿已有本体沿用编号，只提出新增或更新及逐字出处。代码在新建行生成编号，判断和读取位置只追加进 `judgments.jsonl`；按事件时间折叠，同一字段主人优先，模型冲突保留出处。常驻线程首次开口读取最多 2,000 字本体索引，判断流水有更新时在下一轮带上最新索引。面板原话明确给出目标及字段时，例如「纠正：剪辑项目的状态是暂停」或「剪辑项目的状态不是进行中，而是暂停」，代码按编号、唯一名称或别名定位。先写原话再追加 owner 判断，沿用条目编号，出处用当日文件及 owner 时间定位。纠正在当前轮发给模型之前生效。带「纠正／更正」或「不是…而是…」时，条目和字段之间的「的」可以省（「纠正：剪辑项目状态是暂停」）。记入后面板回一行「记下了：某条目的某字段是某值」，没记入则说明原因：随后的答复来自模型，证明不了哪一种。后台模型只追加 model 判断，对话回放仍读原记录。

面板来源默认可读。其他助手会话和系统来源须另外的记忆同意。会话只读已空闲的公开 JSONL 消息格式，系统来源复用原生已授权的读取。增量读者收到新痕迹和按编号、名称或别名命中的条目。超长痕迹分段，判断与位置作为同一条流水提交，失败可从已确认位置重试。本机条目按事件时间重放，主人明确合并同类编号后仍可用旧编号定位。本机面板引用随记录目录迁移。

`OntologySource.read()` 在明确启用时优先读取本机环回的 `/api/ontology`，失败时回读由生产方维护的快照。本地模型推断在启用期间停用。Tako 保留来源条目的稳定编号与旧号映射，只把主人的显式纠正写入本机判断流水。

普通提醒从每天最多六次起步。主人说「以后少提醒我」设为三次，说「今天别找我」当日只保留到点提醒，说「恢复正常提醒」清除限额调整。这三句也认常见的换法（「今天别提醒我了」「提醒太多了」「可以找我了」，`entrusted.pace_mode`）：整句只说这件事才算，句里另有内容（「以后少提醒我喝水」）仍是普通一轮；全在本机比对，不调模型。模型自己改不了这个节奏，提示词让它照实说并告诉主人这几句话。到点件不扣普通件额度。数字和系统提醒的不可逆编号保存在 `ladder.json`，系统来源正文只在内存。数字泡泡显示待办数，悬停展开，点击打开同一份清单。清单标题为「待办 N」，在所有对话中可见，超过 220px 时可滚动。主按钮是「✓ 做完了」，次要操作是「稍后」和「删除」。在别处可点正文打开对应窗口或对话。同一聊天已在前台或面板已贴着对应聊天时，正文只显示文字。前台比对复用原生到场观察，面板比对复用大脑确认的会话，两边都只把匹配的待办编号交给界面。「已完成」在清单底部默认折叠，可用原编号恢复最近三个由主人勾掉或删除的托付。轮询保留折叠状态和滚动位置。

验证新增 `python3 tests/test_memory.py`；离屏走查步骤可用 `held` 件数和 `hover` 布尔值出持有泡泡帧。面板快照失败会报错，不再把零张图打印成出帧成功。
