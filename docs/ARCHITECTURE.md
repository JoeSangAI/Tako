# 架构

Tako 是两个进程：**原生 app**（Swift）有系统权限，管小章鱼、窗口和动手；**大脑**（Python）管会话、模型和规则。面板是大脑提供的一个网页，显示在原生 app 的窗口里。

```
             ┌──────────────── 原生 app（Sources/native）────────────────┐
             │ 小章鱼   窗口跟随   挪窗口让位   填入/操作   听声音   更新 │
             └───┬───────────────────────┬──────────────────────────────┘
       网页里的面板 │              /native/next 取命令，/native/result 回结果
                 ▼                       ▼
             ┌──────────────── 大脑（Sources/brain）────────────────────┐
             │ routes → Companion（chats + turns + hands + lecture）    │
             └───────────────────────┬──────────────────────────────────┘
                            codex_runtime（标准输入输出）
                                     ▼
                              Codex app-server → 模型
```

大脑永远不直接碰窗口：要点、要填、要看，都发一条命令给原生 app。原生 app 不判断该不该做这件事，只判断这一下能不能按。

## 两种线程

判断改动能不能这样写，先看它跑在哪种线程上：

- **大脑线程**：所有窗口共用一条，只跑主人在面板里说的话，有工具、有 shell。
- **触手线程**（`Turns._limb`）：大脑正在别的窗口做事时，主人在这个窗口说的话开一条，工具和规则都一样，做完退订，结果作为消息告诉大脑下一轮。
- **一次性线程**（`Turns._reader`）：听课笔记、从改动里学、开场白、反馈提炼。没有任何工具，用完就退订（`thread/unsubscribe`），Tako 这边不再保留它的事件。所以窗口或材料里写的话，什么也动不了。别人的微信消息不触发任何一轮：主人开口时才读那段对话（`Chats._said_since`），读到的只是材料。

工具调用只认登记在 `on_thread` 里的线程，也就是主人的任务所在的线程（`Hands.on_server_request`）。给一次性线程加工具，就是拆掉这条防线。

## 主人的其他 Agent

Claude Code、Codex 这类 Agent 替主人派活，走 `agents.py`：大脑启动时写 `agent.json`（端口和一个只给 agent 的令牌，权限 600），`tako_cli.py`（装好后是 `tako` 命令）读它，调 `/agent/ask`、`/agent/job`、`/agent/stop`、`/agent/windows`。这个令牌只开这几扇门，面板的令牌也开不了它们：审批卡片（`/decide`）永远只等主人自己点。

一件转来的事就是一个普通的 `Job`：落在那个窗口自己的对话里（`_conversation_of`，面板上显示「〔Claude 转来〕…」），和主人亲口说的走同一条 `turn`，工具、写权限、发送防线、卡片都一样。不同的只有两处：它的话不进 `said`，所以写工作台仍只认主人在面板里的原话；它不 steer 正在跑的一轮，总是新开一件。结局记在 `Job.answer`、`Job.failed`，结束后保留一小时供 agent 来问。

## 末梢和中枢同权

主人线程的权限和主人平时用的 Codex 一样，这是智能的前提：中枢能读到的，末梢也读得到。沙箱只限制写：

- 读：这台电脑上的文件和密钥配置都读得到，读到的内容发给模型。
- 写：本轮作品目录，加上主人在这段对话里说出的路径（`guards.named_paths`）、拖来的文件（`Companion.named`）和TA说话时所在的 Finder 窗口的文件夹（`_what_it_is_about`，整个主目录和磁盘不算）。窗口和消息里的话进不来。
- 要写别处或出沙箱：模型申请，大多不问主人（Joe 2026-11-04：只留关键的卡片）。改文件先把原件备份再放行（`Hands._backed_up`），普通命令直接放行；只有收不回来或离开这台 Mac 的命令（`guards.lasting_command`）和没说改哪些文件的申请走卡片。批准一次，这个会话里同样的事不再问（`acceptForSession`）。

守住的只有少数底线，都不靠模型自觉：发送永远不按、收不回来的操作走卡片、别人的消息触发的一轮没有工具。

## 任务和窗口

一件事是一个 `Job`（`turns.py`）：谁让做的、在哪段对话、哪个窗口、哪条线程。人和任务是分开的：主人切走、把小章鱼拖走都不影响它，工具没写窗口时用的是任务自己的窗口（`Job.window_id`），不是小章鱼现在在的窗口。结果写回那段对话，面板在别处时显示一行“那边做完了”（`_others`）。面板和停止只管当前对话的任务（`_here`）。

动手默认在后台（`Operate.swift`），主人的焦点、鼠标、剪贴板都不碰：

| 动作 | 后台的做法 |
|---|---|
| 点 | 辅助功能的按下（`pressBehindTheOwner`） |
| 输入 | 直接写进字段（`insertBehindTheOwner`），写不进才按键发给那个应用 |
| 填网页 | Chrome 里从页面内部填（`webfill`）：普通框和框架受控的框走元素自己的 setter 加 input 事件，富文本编辑器（Lexical、ProseMirror 等）选中后收一个带文字的粘贴事件，读回核对才算填好 |
| 按键 | 只发给那个应用（`postToPid`） |
| 滚动 | 把下一个看不见的元素滚进来（`scrollBehindTheOwner`），滚完核对真的动了 |

网页的输入框不靠辅助功能：它写不进富文本编辑器，发给后台浏览器的按键也没人收。`fill_input` 遇到浏览器窗口就用 Tako 自己固定的一段页面代码（文字以 base64 作为数据传入，不点、不按键、不碰剪贴板、不提交），经 Apple 事件在那个窗口的当前标签里跑，分几次调用：页面代码和页面自己的脚本隔开，拿不到 promise 的结果，编辑器要过一会儿才认新的选区。主人没开 Chrome 的「允许 Apple 事件中的 JavaScript」或系统没允许 Tako 控制 Chrome 时，回到原来的填法并告诉模型差哪个开关。第一次控制一个应用时系统会弹框问主人，回话前脚本一直卡着，所以原生侧先问一句能不能控制（`mayControl`，不弹框），要问就把系统的框放出去、这一步立刻返回。有的按钮只认真人亲手点（人机验证），后台点了没反应就如实交给主人，不绕过、不再点：后台点过的页面可能卡在提交中，主人亲手点也没反应（Suno 实测 2026-11-04），所以先重新载入那个标签、重新填好，再交给主人。

Chrome 要先打开它的辅助功能才看得到网页里的东西（`askForAccessibleContent`），第一次要等网页真的进来，否则第一眼按不到网页里的东西。它不画被自己窗口盖住的窗口，所以后台时先在应用内部升上来（`surface`），盖在上面的别的应用不受影响；被别的应用盖住时它照常工作。主人正在同一个 Chrome 的另一个窗口里、它完全盖着目标窗口时不能升（会盖过主人），`look` 如实说看不到，主人回到那个窗口再接着做（`coveredByItsOwn`）。

最小化或隐藏的窗口截不到：ScreenCaptureKit 不回话，`Hands.shot` 等 3 秒就放弃，告诉模型。别的桌面上的窗口截得到，但辅助功能看不到它，`look` 会注明只能看。

主人指的是窗口背后的东西，不是那张图：先落到实物上，再一层层往下走，走不通才说。Finder 窗口落到真实路径（问 Finder，不行就用 Spotlight 加窗口里列的文件认出是哪个同名文件夹）和选中的文件，文件的事用命令做。标字（`point`）先看截图，再问页面（屏幕外的内容滚过来；位置问字本身（`AXBoundsForRange`）：Chrome 给元素的框只算露出的部分，长段落露一截就像看得见，屏幕外的还会压扁在页面边上。滚不到就不画圈，直说），最后才容错匹配，数字不容错。标了但窗口不在前台，主人到了再标一次（`_point_when_back`）。同一个工具同样的失败第二次，模型会被告知别再试（`_once_is_enough`）。

末梢和中枢要同等水平（Joe 2026-11-03）：同一个模型和强度（`effort` 不写死，跟主人的 Codex），同一个交付标准（提示词要求读全材料、核对成品），不靠操作窗口取材料。主人把小章鱼粘在窗口上，就是为了不占前台也能把事做完，所以“切到那个窗口”不是流程里的一步，核对成品也不该弹卡片或打开 Word（`look_at_file`）。要的东西先落到实物：聊天记录和收到的文件走 `read_wechat`（文件带本机路径，`wechat_reader.received_file`，没下载的如实说），文档走 `look` 的“文件”路径。

拖动、双击、后台滚不动的地方、微信的输入、递文件要真键鼠。只发给那个窗口的滚轮和点击试过（2026-11-03，带窗口号字段）：微信、WPS 都不动，自写的窗口也只收到事件不响应，所以这条路不通。`ownerSettles` 只在主人恰好在这个窗口时用真键鼠：窗口在前台只是手在动就等几秒，不回去问模型。否则 `waitForFront` 说明是哪一种原因（`not_front`、`covered`、`hand_moving`），工具告诉模型别让主人切窗口，换条路或做完其余。这一轮结束后 `_pick_up_when_back` 悄悄盯着那个窗口，主人哪天自己切过去就接一轮，面板只说不用专门切。主人说了别的话就取消；窗口在前台却还是做不成，接两轮就放下，不再花模型调用。

填入和递文件内容是确定的，不用模型接：`_hold_fill` 记下这一步，回复模型“已排好”，`_place_when_back` 盯着目标窗口。主人切到那里，软体跟过去（`followTo`，不动任何窗口），手一停就由程序放好，放之前重新核对微信打开的是哪段对话；原来开着的面板等放完才跟过去，也不抢键盘（`followDone`）。再调一次替换排着的，主人接着说话时模型会被提醒，要不要就由它传 `cancel`。窗口没了、搜不到人或等了半小时，都告诉主人并给出文件。按给后台应用的 Cmd+V 不生效（TextEdit 实测 2026-11-02），所以微信的粘贴只能等前台。

## 主人指给 Tako 看

主人按住 ⌃，在粘着的那个窗口上用鼠标指（`Pointing.swift`）。只认这个窗口、只认单独的 ⌃，别处和别的组合键一律原样放给应用；代价是这个窗口里 ⌃+点击不再是右键，触控板两指点照旧。

- 按在字上拖：把按压去掉 ⌃ 原样交给应用，由它自己选字，松手后从焦点元素读出选中的字和位置（`AXSelectedText`，网页用 text marker），读不到就读窗口上那一条。
- 别处拖、画一圈：圈住拖过的范围。只圈住一样东西就当那样东西；在一张大图上圈一小块是“图片局部”，带上在图里的位置和圈里的字。
- 点一下：辅助功能找到下面最近的链接、图片、按钮、输入框、段落或条目；什么都找不到（微信）就取按压处同一种颜色的那一块（气泡）并识字。再点同一个就取消。

要快（Joe 2026-11-04：慢了十倍）：墨圈在松手那一刻就画，用按住 ⌃ 时提示框已经查到的东西，后面再补里面的字；按下 ⌃ 时先拍一张窗口，松手后只识圈里那一小块（实测辅助功能 1–50 毫秒，整窗识字 1–6 秒，只识圈里 0.2–0.5 秒）。

圈不是截图，是手指：指的那一刻就落到实物上（链接地址、图片地址、文件路径、所在文档、字），因为TA说完话前页面可能已经滚走。墨圈用 `Enchant.circle` 同一种笔画，带编号，留到发送时飞回小章鱼；滚动就淡掉，面板里的块还在。面板把块和话一起交给 `/ask`（`points`），大脑把它们作为“只是材料”放进这一轮（`prompts.pointed_at`），指到的文件和所在文档可写，和拖进来的文件一样。

## 一轮卡住时

大脑线程会越来越重。主要不是字，是窗口截图：一张只占很少 token，却有上百 KB，断线重连后要全部重传。所以有两条线（`_compact_if_long`）：token 到 `COMPACT_AT`，或截图到 `COMPACT_PICTURES_AT`，就在这轮答完后压缩。

一轮等模型时，Codex 自己会重试，也会把连接换成整包上传的 HTTP。Tako 不替它重试，只做三件事（`_finish`）：

- 把重试原样告诉主人（`trouble`），面板不再显示上一步。
- 重试不算有进展，不重置 15 分钟的静默上限。
- 线程已经很重、又连续传不上去时，停掉这一轮，下一句换轻线程（`_leave_thread`），带上这个窗口最近说的话。不重放，避免把做过的事再做一遍。

一轮进行中主人又说话：同一窗口、没带文件时用 `turn/steer` 送进这一轮（`_steer`）；带文件的排在这段对话后面，面板显示在排队（`queued`）。别的窗口说的话不排队，大脑忙就开触手。

## 加一个工具

1. `prompts.py`：在 `TOOLS` 里声明，`STEP_NAMES` 里起名字，需要时在 `PROMPT` 里说明。
2. `hands.py`：在 `_run_tool` 里实现。收不回来的事走 `_card`。出异常不用管，模型会收到一次失败，这一轮继续。
3. 要动窗口时：在 `Hands.swift` 的 `run` 里加一条命令。
4. 测试：`tests/test_turns.py` 里写一个主人看得到的场景。


- `test_guards.py`：底线规则。规则能直接调用就直接调用，只有 Swift 和“某段代码不能用某个东西”才查源码。
- `test_turns.py`：真的启动大脑，一头是它的 HTTP 路由，一头是 `tests/fake_codex.py`（和真 Codex 一样的消息，不用模型、不联网），测试自己扮演原生 app。场景写在问句里，比如模型中途失败、工具卡住时按停止。
- `--selftest`：小章鱼的动作和帧率。要看屏幕，不进 CI。
- `--showcase`：在屏幕中间的地上把一套装扮的动作演一遍（放大三倍、带画出来的光标和字幕），录屏用。和自检一样不开面板、不挪窗口、不碰真光标。

## 隔离运行

设了 `TAKO_HOME`，所有状态都写到那个目录，回传也关掉。原生 app 和大脑都认它，正式版绝不能设。

```bash
open -n dist/Tako.app --env TAKO_HOME=/tmp/tako-test --args --selftest
```

面板打开时可能挪动真实窗口，自测不会打开面板，也不检查更新。
