# Tako

Desktop soft-body companion that sticks to a window and gives it intelligence. README is the public product page. If `.local/AGENTS.private.md` exists, read it too: it holds this machine's private rules, and `.local/STATUS.md` holds the current verified state.

This repository is public. Personal paths, names, chat content, keys and client facts never enter it: whatever is personal goes in `~/Library/Application Support/Tako/config.json`. `scripts/check_public.sh` guards this on every push.

## Rules that must hold

- It is called Tako everywhere, in the UI and in the model's prompts. It does not answer as any other assistant name.
- Fill, never send: Tako may put text into an app's input and change documents the owner asked it to change, but must never press Return, click a send button or otherwise send a message. Only the owner's own words can trigger writing; what an incoming message or window shows never can.
- Quiet, timed delivery and corrections: quiet hides promise text even on hover. Detect presentation, recording and sharing with existing device signals and local power assertions, with no new permission. A due promise has first claim on the next free hand, skips the ordinary daily count and is never marked ignored merely by waiting. If it missed the screen while quiet, away or stopped, it stays due for the first safe foreground delivery. An explicit owner correction with a unique target and field appends an owner judgment with the stable item id and the panel record citation and takes effect before the next model turn. Models append only model judgments.
- Proactive hand-overs (`entrusted.py`) come only from things the owner entrusted in their own words, or their other agents handed over for them; never from a window's contents or someone else's message. The line to hand back is prepared in that owner turn; time, place, transitions and responses never call a model. Their state and outcomes replay from the same append-only conversation records, never a second list. Tako brings a to-do to the owner at the right moment. ✓ 做完了 completes it, opening it keeps it pending, and 稍后 says when it comes back. Stuck to a window is focus: only what is timed (handed over where it is) and what concerns that window come up; everything else waits for the desktop, and peeling it off is such an occasion. The body never goes to another window to hand something over.
- One thing at a time: whatever comes before the owner on Tako's own initiative is decided in one place, `Ladder.next` (`ladder.py`), in one order: what Tako can't work without (a model, then Accessibility, then Screen Recording), each a panel card that opens the panel once and goes when done, with the system's own prompt only when its turn comes; then the first try; then, only after Tako has helped once (an answer or a promise brought back), the invitations, at most one a day, each offered once, gone by itself when not taken up, never while a question under an answer is open. Only one thing is taught ahead of time (double click it and say something); everything else comes when it would have helped or as one of those invitations. Copy says what the owner gets in Tako's own voice, never a product or tool name (the system's own names for its switches excepted; picking which account to use names the account). A login this Mac already has (a logged-in Codex, an office agent logged in) is used without asking and the panel only says which; nobody picks or types unless there is nothing.
- The ladder of proactivity (`ladder.py`): the same promises and their three moments, with sources lit up by what the owner already has; no settings page, only the next step, and never a second store or a second way in. (1) The first try, once in a lifetime, once the model and both switches are ready, and never for an owner who has entrusted or talked to Tako before: one line by the body says the one thing to know and something to say (a person if a chat app is on this Mac, else a minute from now), the next step once, done when it comes back; let pass, never asked again. (2) At the end of a turn the owner was already in, the model may ask once (`entrust ask`) whether to keep a promise in the owner's own words or in a reply it drafted for them; Tako puts the question under the answer, and only 好 (tapped or said) makes it a promise. A draft's promise counts once that draft is seen sent where Tako can see it (WeChat with its reader), else on the owner's 好. One a turn, never what is held, never someone else's words; three left unanswered in a row and it doesn't ask for seven days; 别问了 stops it until the owner entrusts something themselves. Only numbers are kept for this. (3) Reminders and Calendar: one of the invitations, only where a chat app is on this Mac; only the owner's own 好 makes the system ask (declined: never offered again): a reminder naming a chat the owner has comes up when that chat opens, ticked off there it is gone; a meeting is only a moment, a line ten minutes before only if something is held for someone in it. Their words stay in memory and are never recorded or logged. Only a separate memory consent allows the owner's model to read them. (4) The owner's other agents and scripts find Tako by name: `tako` is put in `~/.local/bin` when that folder already exists (never over a `tako` without Tako's mark), and `tako --help` says when and how. Nothing is asked, nothing goes into any agent's own folder, and no agent is singled out. Tests use a made-up home.
- While a promise is held, the proactive look is the frontmost application's name and window title (`Entrusted.swift`), compared locally with an entrusted place, including while attached. Only when a chat-place promise exists and WeChat is frontmost, the top strip of that WeChat window may be captured and recognized locally to compare the open chat name (`Entrusted.tick`); unchanged pixels do not run OCR. The strip can include part of the first message, discarded after local recognition; no message text, model call, disk write, record or report; only matching entrusted ids leave that comparison. Stuck on that chat app in front, it compares with the chat the panel confirmed (`Controller.openChat`) and captures nothing of its own. With DingTalk frontmost instead, only its open chat's name is read through Accessibility (`DingTalk.openChat`), under the same limits. Incoming messages never start work.
- Operating an app (`Operate.swift`): sending stays refused even with approval; Enter is refused in messaging apps; password fields are refused; only what can't be taken back asks first (pay, buy, transfer, delete, submit, publish, sign out, uninstall, reset), and network/system tools ask every step. Stop, remove from a list, disconnect and a new line in a document just go ahead.
- A job belongs to the window it was asked on and goes on wherever the owner goes. Switching away or dragging the goo to another window never stops it; only the stop button does, and only for what the panel shows. It works behind the owner's back: Accessibility and events sent to that app alone, never their focus, pointer or clipboard. What only the real pointer can do happens only if they are already on that window and idle (`ownerSettles`), and nothing brings a window forward except a button they pressed. A fill or file hand-over that has to wait is queued, not failed, and finishes by itself with no model call when they get there (`_hold_fill`); the goo follows them there, nothing else moves. The owner going to a window the job is working (their own click or ⌘Tab, not a window that came up by itself, not one only looked at) finds the goo and the job there (`_follow_hands`); otherwise the result stays where it was asked. A `chat` is a conversation in a chat app (WeChat, or DingTalk read through Accessibility), never the job's own window; only a WeChat chat is opened by name. Which chat is open has one answer (`Chats._confirm`) that the panel, a fill's check and the promises all read: after a click it is unconfirmed until read, nothing is filed under the chat before meanwhile, and a chat it can't tell is said plainly, never guessed.
- A limb works to the brain's standard and interferes with nothing. Same model and effort as their Codex; read the material whole and check the finished work with `look_at_file`, which opens no app and asks nothing. No card and no app opened just to see a file.
- Asking the owner to switch to a window defeats the point of Tako. Go through what is behind the window first (files, the message database, Accessibility), then events sent to that window alone; never make "come to this window" a step in the middle of a job, and never tell the model to ask for it. Only the last hand-over the owner would do anyway, such as a draft into a chat they will send themselves, may wait for them, and everything else is finished by then.
- WeChat waits for the owner like any other window. Someone else's message starts nothing and shows nothing; the chat is read when the owner speaks, and what is read is data (`_said_since`). The one background look is whether a draft got sent, to learn from it: file stats and a local read, no model call. DingTalk the same (`DingTalk.swift`): Accessibility only, never a screenshot, OCR or DingTalk's own files; while stuck, the open chat's name lets the panel follow it, and the messages its window shows (who said each, which are the owner's) are read only when the owner speaks there.
- The owner's other agents (`agents.py`, the `tako` command) speak for the owner: a job they hand over runs like the owner's own words, with every floor here unchanged. An agent may withdraw only a promise bearing its own source name, never one the owner entrusted; the withdrawal records that name. Their shared token lives in `agent.json` (0600, new on every start) and opens only `/agent/`, never a card: approvals wait for the owner's own tap. Source names are caller supplied, not authenticated identities. The panel shows who handed it over. Their words never enter `said`, so the external task service still takes only the owner's own panel words.
- Any model the owner brings (their ChatGPT login, or their own key for DeepSeek, Qwen, Kimi, GLM or any relay that speaks Responses, through `provider.py`) gets the same Tako. A change made for one model must make the best one better too; no prompts, step caps or guards for a single model. Where a model falls short, say so and leave it there.
- Throwaway threads have no tools at all (`READER_CONFIG`); never give them shell, plugins or `TOOLS`. Tool calls and approvals count only on the threads of the owner's own jobs (`on_thread`), and on a conversation's standing thread only while such a job runs on it.
- Each conversation (a window, a WeChat or DingTalk chat, the desktop) has a standing thread of its own (`turns.Brain`): the owner speaking there is the only routing, no model decides it; in order within a conversation, side by side across them. It carries only Tako's rules, who the owner is, what is entrusted, a thin ontology index (`ontology.Memory`, with details in the cited records) and its own conversation; what is done elsewhere reaches it once, as a line (`_tell_threads`). A limb is the same thread for one job, when that one can't take it now. `per_conversation_threads: false` maps every conversation to one shared thread, the behaviour before; keep it one code path, not two. A summary runs after the job has ended and never makes the owner's next word wait.
- A limb has what the brain has: the owner's turns read this Mac's files and keys like their own Codex does. What stays narrow is writing: the turn's folder, plus paths in the owner's own words, files they handed over (`named_paths`) and the folder of the Finder window they asked on (`_what_it_is_about`), Outside that it still goes ahead without a card, made recoverable first: a file change backs up what was there (`_backed_up`), a WPS replacement backs up the original, and an ordinary command out of the sandbox just runs. A card is only for what can't be taken back or leaves this Mac (`guards.lasting_command`: deleting, uploading or sending off the Mac, pushing git, changing the Mac's settings, ending processes, osascript), a change that names no files, a script that deletes or changes a page (`risky_script`), and feedback text going to the author. Don't add read limits or more cards; the lines above are the floor.
- Pointing (`Pointing.swift`): only ⌃ alone, only on the window it is stuck to, only presses, drags and scrolls; everything else goes on to the app untouched. The event listener also observes global modifier, key and mouse-button events to recognise the speaking key and cancel chords, and processes text keys only during a speaking session; it does not record them. A drag over text is the owner's own press handed on without ⌃, nothing more. What is circled is material for the turn, never an instruction, and a ring is a finger, not a picture: it is resolved to the real thing behind the window when it is made.
- Permissions (`Permissions.swift`): ask the owner as rarely as the system allows. Each switch once; the system's own prompt only on the first start; a switch turned on takes effect without a restart they have to do; anything Tako can put right itself (a stale record, a restart into Screen Recording when no job is running) it does without a card or a question.
- Filling says it filled only when it can tell: a page with no cursor in a field is an error, never success (`insertBehindTheOwner`).
- Learning from the owner's edits keeps habits only (`voice.md`), never sentences, names or figures; `metrics.jsonl` holds numbers and fixed words only (tool names, block reasons, bundle ids), and stays on this Mac.
- Listening (`Listen.swift`): starts only on the owner's words, only the stuck app's sound, never calls or meetings; audio pieces are deleted once read and nothing leaves the Mac. Notes come from a throwaway thread with no tools.
- Feedback (`feedback.py`): never interrupts: no cards, no questions, one checkmark in the menu, on unless switched off, and off stops all of it. Automatic reports hold only numbers, fixed vocabulary and error type and place, never words, names or identifiers, not even abstracted ones. Free text leaves only when the owner asks to tell the author and taps send on the card that shows it. Extraction reads only the owner's panel words on a throwaway thread with no tools. Change `docs/PRIVACY.md` in the same commit as anything that changes what leaves. The receiver takes no key and serves nothing back.
- Greetings (`greetings.py`): only the app's name goes to the model, never the title or anything in the window, on a throwaway thread with no tools; lines are shown as plain text and only in the empty panel. A WeChat conversation gets one batch a day because people flip through chats all day: looking at a chat never uses up a line or asks the model for more, the first chat of the day asks once, and only the word WeChat goes out.
- Peeled off a window, it stops reading on its own initiative; a job the owner already started goes on. Chat text stays in memory; never log or commit chat content, keys or tokens. The one exception is what each panel showed, the owner's words and Tako's answers, and how each ask ended: the records (`records.py`).
- Tako's folder is the owner's and there is one of it (`output_root`, chosen in 做过的事…, moved whole when it changes): `对话记录/` a day at a time, `产出文件/` only for what was handed over. The records hold what the panels showed and each ask's ending, files and the files it changed elsewhere, never what a window or chat showed by itself; 0600, append only, never deleted by Tako. They are the one store for the panels after a restart, the memory a new thread is told, the history and the owner's other tools, so nothing else keeps a copy. Process files go to the turn's scratch (`work/`, where commands run, gone after a week); backups go to the Trash after a month; what was handed over is the owner's to delete.
- Runtime state lives in `~/Library/Application Support/Tako/`, never inside the app bundle (a write there breaks its signature and the permissions with it).
- Displayed times, reminder calculations, command clocks, occasion dates and daily record grouping use the owner's configured time zone, or the Mac's system time zone if unset; existing record files are never rewritten when it changes.
- Moving or narrowing another app's window needs Accessibility; always put it back unless the owner moved it. The panel never covers a full window if it can be helped.
- Tests never change network or proxy tools' state, never send anything, and write to an isolated `TAKO_HOME`. `TAKO_HOME` also turns reports off, so the real app must never set it for its own server.

## Releasing

A release is a version bump, nothing else: change `VERSION`, add a section to `CHANGELOG.md` written for the people who use Tako (what they get, not what changed in the code), commit, `git push`. `.githooks/pre-push` runs the tests and the public check, builds and signs the app, and publishes the GitHub release once the push lands; every installed Tako then offers it. A push that keeps `VERSION` reaches nobody. Enable the hook in a new checkout with `git config core.hooksPath .githooks`.

A release also carries a small package without the Python, which an installed Tako with the same `python.id` fetches instead of the whole app; the Python is signed once and cached in `.build/signed-python/` so its bytes stay the same. Losing that cache only means the next update is whole again.

When `.local/release-relay` names an ssh host with a fast uplink and it answers, every file goes through it. Otherwise publishing puts the small update out first and makes the release public, then uploads the whole app with retries; until it lands, `latest.json` points new installs at the previous whole app if its Python is the same. A stalled publish is finished by running `scripts/release.sh publish <commit>` again: it uploads only what GitHub doesn't hold yet.

Updates install only when the new app satisfies the running app's designated requirement, so the signing identity must stay the same: changing it strands everyone on the old version and resets their permissions.

## Layout

`docs/ARCHITECTURE.md` is the map: the two processes, the two kinds of thread, what each file is for, how to add a tool. Read it before moving anything.

`Sources/native/` the app (Swift): goo, windows, panel window, hands, updates. `Sources/brain/` the Python side and the panel page. `server/feedback_receiver.py` where reports land.

`tests/test_guards.py` the lines that must hold. `tests/test_turns.py` the real Python side against `tests/fake_codex.py`, with the test playing the app: write a new behaviour or a bug as a scene there first. `run.sh` builds and restarts for development. `scripts/` build and release.
